2026 个人 AI 技术栈最小清单

核心原则：在技术通胀的时代，克制是最高的生产力。 目标：不争论框架，不囤积模型，只交付可运行的智能体。

🛑 负面清单 (Not-To-Do List)

在做任何加法之前，先确认你没有做以下蠢事：

  • ⬜拒绝模型崇拜：不碰模型训练，不买显卡，不折腾 CUDA 环境。
  • ⬜拒绝架构过度：个人项目严禁引入 Kubernetes 和企业级微服务。
  • ⬜拒绝 RAG 滥用：90% 的场景不需要向量数据库，关键词搜索 + 上下文缓存足矣。
  • ⬜拒绝框架松鼠症：不学 LangChain 的 100 种用法，只用最基础的工具封装。

✅ 最小技术栈 (The Minimalist Stack)

如无必要，勿增实体。这是你的生存套件：

1. 语言与环境

  • - Python：唯一选项。
  • - 理由：AI 的母语。除了 Python，其他都是方言。

2. 模型层 (Model as a Service)

只关注 API 调用，像用水电一样使用智力。

  • - 主力 (Smart)：GPT-4o / Claude 3.5 Sonnet
  • - 用途：复杂逻辑推理、代码生成、长文本分析。
  • - 副手 (Fast)：DeepSeek-V3 / GLM-4-Flash
  • - 用途：批量处理、简单分类、高频对话。
  • - 关键技能：
  • ⬜Prompt Engineering：结构化提示词编写。
  • ⬜Function Calling：让模型连接真实世界的唯一桥梁。

3. 编排层 (Orchestration)

这是 2026 年的核心战场。

  • - LangGraph：唯一推荐。
  • - 核心逻辑：State (状态) + Edge (流转)。
  • - 心法：把“思考过程”画成图，而不是写成链。

4. 数据与记忆 (Data & Memory)

回归朴素，拒绝高大上。

  • - 存储：SQLite / DuckDB / JSON
  • - 原则：能用文件解决的，绝不起数据库服务。
  • - 工具：Pandas
  • - 用途：清洗数据，喂给 AI 吃。

🛠️ 工程规范清单

像外科医生一样精准管理你的代码。

  • ⬜目录结构： 
      project/
  ├── agents/       # 大脑 (Planner, Executor)
  ├── tools/        # 手脚 (File, SQL, Search)
  ├── graphs/       # 神经 (Main Logic)
  ├── memory/       # 记忆 (JSON/SQLite)
  └── main.py       # 启动
  • ⬜版本控制：Git 是底线。每个 Commit 都是思考的快照。
  • ⬜README：必须写。第一行就要说人话：“这个 Agent 解决了什么具体问题”。
